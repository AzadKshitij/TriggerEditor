# What's new in Trigger Designer v0.1.0-alpha.3

!!! warning "Alpha build"

    A test build for Windows. Expect rough edges. The setup program and the portable
    zip are new in this release and have not yet been tested on a clean Windows install.
    Please report what you find using the
    [bug report template](https://github.com/AzadKshitij/TriggerEditor/issues/new/choose).

## New

- **A setup program.** `TriggerDesigner-0.1.0-alpha.3-setup.exe` installs for your
  Windows user only, with no administrator rights. Choose **Full** (the editor, the
  command line and the AI tools), **Editor only**, **Command line and AI tools only**, or
  **Custom**. It adds Start menu entries, can add the `tds` command to your PATH (off by
  default), and removes that PATH entry when you uninstall.
- **A portable zip with everything.** `TriggerDesigner-0.1.0-alpha.3-windows-portable.zip`
  unzips to one folder with the editor (`TriggerEditor.exe`) and the command line
  (`tds.exe`). The single-file editor is still available as a lighter download with no
  command line or AI tools.
- **One short command: `tds`.** It replaces `trigger-designer-cli` in the help and the
  examples; the long name still works.
  - `tds run flow.tds` runs a workflow.
  - `tds validate flow.tds` checks it.
  - `tds open flow.tds` starts the editor.
  - `tds mcp` starts the AI tool server.
- **AI tools (MCP server).** An AI assistant can look at your workflows and their data,
  and build or change workflows, within a policy file that you control. It can:
  - list the node types and describe each one;
  - list the files in your workspace and profile a data file;
  - read a workflow with its settings, and check it, including the data it reads;
  - preview columns, statistics and the first rows at any node, if your policy allows;
  - create a workflow, or patch one. Changes are a dry run until you apply them, and
    applying needs the file's hash, so a file changed by someone else is not overwritten.

  Set it up with the [AI tool guide](guide/mcp-server.md).
- **Open `.tds` files from anywhere.** Double-click a workflow in Explorer, use
  **Open with**, or drag one or more `.tds` files onto the editor window or onto the
  canvas. Other file types are refused. In the portable build, **Help > Open .tds files
  with Trigger Designer…** registers the file type for your user.
- **File > New Window** (`Ctrl+Shift+N`) opens a second, separate editor window.
- **Review outside edits.** If another program changes a workflow while you have it open,
  a banner offers to review the change. Accepting it is one undo step named **External Edit**.
- **Optional modules.** **Help > Optional modules** lists data packs you can add. Nothing
  downloads without a consent screen first. This version's list is empty.
- **Names from the AI tool.** Node names set by an AI tool show in the editor.

## Improvements

- **Problems show before you run.** `tds validate --check-data` and the AI tool's
  `validate` catch a missing column, and a text column used as a number in a Formula or
  Filter, with the real column name in the message. Those used to appear only when the
  run failed.
- **Full file paths.** Saved file paths are written in full, not relative to the workflow.
- **CSV files load as text.** The AI tool knows this and says so, so it does not treat a
  column of codes as numbers.
- **Clear start-up for the AI tool.** The server prints the workspaces and the policy it
  is using, and refuses to start on a bad path or an invalid policy file with a message
  that says which.
- **Policy changes apply at once.** The policy file is read on every call, so you do not
  need to restart the server after you change it.

## Fixes

- The AI tool server works from the packaged build. Its data tools run the packaged
  `tds.exe`, so they no longer need Python installed.
- `tds --version` and the program's version agree (`0.1.0-alpha.3`), and a test keeps them
  equal.
- The command line no longer prints a file-watcher warning on its error output.
- The optional module download dialog shows progress correctly for very large modules.

## Known limitations

- **Unsigned.** Windows may show a warning the first time you start the program or run
  the setup. See [Install](../install.md#first-start-the-windows-warning).
- **The file association stays after uninstall.** Remove it in **Settings > Apps > Default
  apps** if you want it gone. On a PC where Tableau owns `.tds`, Windows keeps Tableau as
  the default; pick Trigger Designer there once.
- **No drag of a workflow tab between windows.** Open a second window with File > New
  Window, then open the file in it.
- **The crash with code `0xC0000409`** from alpha 1 has not been fixed yet. Save often.
- **Long names still work.** `trigger-designer-cli` and `trigger-designer-mcp` are kept for
  existing scripts and AI tool setups.
